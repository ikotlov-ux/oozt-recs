# oozt-recs

Автоматизированное формирование природоохранных рекомендаций (мероприятий) для особо охраняемых зелёных территорий (ООЗТ) и природных территорий города Москвы. Скрипт назначает мероприятия по кварталам (учётная единица — квартал; границы выделов или полигонов экосистем используются как геометрия для расчёта участков работ) на основе ГИС-слоёв, ЦМР и данных о встречаемости видов, для каждого назначения формирует текстовое основание с числовыми значениями и собирает картографические схемы и отчёт.

## Нормативная основа

Перечень мероприятий и их нумерация соответствуют разделу 4 «Мероприятия по сохранению биоразнообразия при проведении работ по содержанию ООЗТ и ПТ» Временного регламента содержания особо охраняемых зелёных территорий и природных территорий города Москвы, утверждённого совместным приказом Правительства Москвы от 30.12.2025 № 05-09-310/25 (и др.), пункты 4.1–4.13. Отдельные позиции соответствуют инженерно-техническим и противоэрозионным мероприятиям (ИПЭЭ-1…ИПЭЭ-3). Видовые справочники: Красная книга Москвы (3-е изд., ПП № 745-ПП от 02.07.2019) и перечень инвазивных видов (ПП № 369-ПП от 03.03.2026) — см. разделы ниже.

### Данные, которых не хватает (по обсуждению 04.11.2026)

Реализовано (обновление 10.11.2026): слой стихийных троп скачивается из OSM автоматически (тег `informal=yes`); категории Красной книги Москвы определяются по справочнику (столбец «КК Москвы: категории»); списки таксонов инвазивных видов по жизненным формам заполнены (II.1/II.2, перечень к ПП № 369-ПП).

По-прежнему не хватает:

- точки орнитологов и зоологов: гнездовья, целевые виды, стаи ворон (IV.5);
- материалы лесоустройства Измайлова — для блока «только по лесоустройству»;
- границы зон отдыха (III.2);
- список растительных сообществ для гнездовий (I.4).

Реализовано (обновление 12.11.2026): слой дренажных канав (III.8), векторные болота (I.8), точки рекреации (тепловая карта на схемах), твёрдые и грунтовые дороги («Колокольчик», схемы), лесопатология ПВН (V.1–V.6), справочник водоёмов `water_catalog.csv` (I.9–I.11), деление лугов на естественные и антропогенные.

### Естественные и антропогенные луга

Антропогенные луга — газоны (тип 503) и бурьян (тип 222); все остальные луговые типы считаются естественными. Правило «луговые естественные» (I.7 выкашивание, III.5 защита склонов, луговое местообитание «Колокольчика») срабатывает на любом луговом типе, кроме содержащего «газон», «бурьян», «503» или «222» (маркеры ищутся и в кодах: «Газоны 503», «бурьян 222»). Правило «луговые антропогенные» — наоборот, только на газонах и бурьяне; просто «луговые» — на любом типе со словом «луг».

## Способ назначения в таблице мероприятий

Способ назначения каждого мероприятия задаётся столбцами таблицы мероприятий. Скрипт читает правило и все его параметры прямо из Excel, поэтому способ назначения можно менять без правки кода.

| Столбец | Что указывать |
| --- | --- |
| Правило назначения | одно из правил ниже (выпадающий список) |
| Типы полигонов | типы полигонов слоя территории через запятую: лесные, луговые, водные, околоводные, болотные…; «любые» или пусто — все полигоны |
| Виды: категория | инвазивные, охраняемые, прочие; «любые» или пусто — все |
| Виды: группы организмов | сосудистые растения, грибы, лишайники, млекопитающие, птицы, низшие позвоночные, насекомые, редкие экосистемы…; «любые» или пусто — все |
| Виды: таксоны (лат.) | латинские названия видов или родов через запятую (например, Corvus); пусто — все виды |
| КК Москвы: категории | категории Красной книги Москвы (0–5, «О») через запятую; например «1, 2, 3»; пусто — без учёта Красной книги |
| Только стихийные тропы | «да» — тропы у находок считаются только по слою стихийных троп OSM (`informal=yes`, скачивается автоматически); «нет» или пусто — по всей дорожно-тропиночной сети |
| Виды: данные | точки, полигоны, SDM; «любые» или пусто — все |
| Расстояние, м | ширина полосы у воды или радиус вокруг точек видов |
| Окно плотности, м | радиус скользящего окна растра плотности |
| Квантиль | порог плотности; 0,75 — верхний квартиль |
| Уклон более, % | порог уклона |
| Порог SDM (0–1) | вероятность модели, начиная с которой участок учитывается |
| Мин. площадь участка, га | минимальная площадь участка внутри полигона |
| Мин. доля полигона, % | минимальная доля площади полигона под участками; пусто — общий порог из окна скрипта (25 %) |
| Мин. / Макс. площадь выдела, га | ограничение мероприятия по площади выдела (например, III.3 — от 1 га, III.4 — до 1 га) |
| Плотность троп, м/га (порог) | абсолютный порог плотности троп для правила «плотность троп в полигоне» |
| Водоёмы (только) / Водоёмы (кроме) | список водоёмов из `water_catalog.csv`: только эти / все, кроме этих |
| Мин. длина в полигоне, м | минимальная суммарная длина линий (дренажных канав) в полигоне |
| Точки: категория | категория точек лесопатологии (V.1–V.6) |
| Зона от границы, м | ширина кольца от границы ООЗТ («Колокольчик»: 500–1000 м) |
| Полоса от дорог, м | ширина полосы от твёрдых дорог, исключаемой из участка («Колокольчик»: 100 м) |
| Буфер от дорог, мин./макс., м | полоса от дорожной сети для правил «буфер дорожной сети» (I.4: 50–100 м, I.5: 0–50 м) |

Для правил по участкам действует и порог доли полигона (см. ниже). Если «Правило назначения» пусто, правило и параметры определяются по ключевым словам «Метода выявления», как в прежних версиях (врановые → уклон → тропы у точек видов → инвазионные виды → тропы у воды → плотность троп в окне → плотность троп на полигон → тип полигона).

Кнопка окна «Записать правила и описания в таблицу» (или `--update-table таблица.xlsx`) добавляет в таблицу недостающие столбцы правил и заполняет их там, где правило пусто, значениями, которые скрипт сейчас определяет по тексту метода. Кроме того, она добавляет выпадающие списки, лист «Справка по правилам» и столбец «Процедура назначения (как работает скрипт)» с полным описанием расчёта каждой строки. Перед первой записью создаётся копия `…_до_правил.xlsx`.

Готовая таблица мероприятий с заполненными правилами назначения, листом «Справка по правилам» и описанием процедуры для каждой строки лежит в репозитории: [`measures/meropriiatiia_s_pravilami.xlsx`](measures/meropriiatiia_s_pravilami.xlsx). Её можно указать в поле «Таблица мероприятий» как есть или взять за образец для своей таблицы.

Отчёт (раздел «Как рассчитаны мероприятия»), лист Excel «правила», журнал `run.log` и окно скрипта показывают для каждого включённого мероприятия правило, откуда оно взято (столбцы таблицы или текст метода), параметры, подходящие слои видов и число назначенных полигонов. Неизвестное название правила или ошибочное значение параметра не останавливают расчёт: мероприятие пропускается, а причина видна в окне и в журнале.

## Слои видов и редких экосистем

Слои видов загружаются одним списком. Для каждого слоя указываются:

- категория: инвазивные, охраняемые (виды Красной книги и другие охраняемые или редкие виды, редкие экосистемы) или прочие (например, все наблюдения птиц для плотности врановых);
- группа организмов: сосудистые растения, грибы, лишайники, млекопитающие, птицы, низшие позвоночные, насекомые, редкие экосистемы; новую группу можно ввести вручную;
- тип данных — определяется автоматически: точки, полигоны (векторные слои) или SDM (растр вероятности 0–1).

Название вида берётся из поля с латинскими названиями, которое находится автоматически; можно указать поле вручную (например, название редкой экосистемы). У растров SDM название вида — имя файла. Мероприятие использует слои, подходящие по столбцам «Виды: категория», «Виды: группы организмов», «Виды: данные»; «Виды: таксоны» дополнительно отбирает записи по латинскому названию. Конфигурации прежних версий (`invasive_*`, `rare_*`, `fauna_points`) читаются автоматически: инвазионные → «инвазивные», редкие → «охраняемые», фауна → «прочие, птицы»; группа у растений — «не указана».

## Константы

Значения по умолчанию для правил, определённых по тексту метода, и шаг сетки задаются константами в начале `oozt_recs.py`: `CELL` 10 м (шаг сетки растров), `TRAIL_WINDOW_M` 50 м, `CORVUS_WINDOW_M` 500 м, `RARE_BUFFER_M` 50 м, `SHORE_BUFFER_M` 50 м, `SDM_THRESHOLD_RARE` 0,75, `SDM_THRESHOLD_INVASIVE` 0,95, `QUANTILE` 0,75.

## Требования

Python 3.10 и новее, окружение с геопространственными пакетами:

```
geopandas, pyogrio, rasterio, shapely, numpy, pandas, scipy, matplotlib, openpyxl
```

Дополнительно: `contextily` — подложка OSM на схемах, `pywin32` — сохранение отчёта в PDF и DOC через Microsoft Word (в conda-окружениях Windows обычно уже есть), `tkinter` — окно выбора исходных данных (входит в стандартную поставку Python и conda).

Пример создания окружения:

```bash
conda create -n gis python=3.11 geopandas pyogrio rasterio shapely scipy matplotlib openpyxl contextily -c conda-forge
conda activate gis
```

## Запуск

```bash
# окно выбора исходных данных
python oozt_recs.py

# повторный запуск с сохранённой конфигурацией, без окна
python oozt_recs.py --config config_local.json

# то же окно, предзаполненное из конфигурации: можно поправить слои и запустить
python oozt_recs.py --config config_local.json --gui

# отчёт только по выбранным кварталам (или листам / группам в режиме экосистем)
python oozt_recs.py --config config_local.json --kv 1,2,17,40
python oozt_recs.py --config config_eco.json --kv B3,C4

# записать в таблицу мероприятий столбцы правил, справку и описания расчёта
python oozt_recs.py --update-table meropriiatiia.xlsx

# пересобрать только отчёт по уже рассчитанной таблице
python oozt_recs.py --config config_local.json --report-only

# без подложки OSM
python oozt_recs.py --config config_local.json --no-basemap

# в Jupyter: вставьте весь файл в одну ячейку — автозапуска не будет; затем
cfg = Config.load("config_local.json"); run(cfg)      # или main()

# форматы отчёта (по умолчанию docx,pdf; doc — Word 97–2003; пусто — только Markdown)
python oozt_recs.py --config config_local.json --report-only --formats docx,pdf,doc
```

Скопируйте `config.example.json` (кварталы и выделы) или `config.example_eco.json` (слой экосистем) в `config_local.json` и подставьте свои пути. Файлы `config_local*.json`, `config_pc.json` и `config_used.json` исключены из репозитория, чтобы локальные абсолютные пути не попадали в историю.

## Окно выбора данных

Все исходные данные задаются в одном окне из пяти блоков:

1. Таблица мероприятий — сразу после выбора показано, сколько мероприятий в таблице и сколько из них включено.
2. Слой территории — режим «Кварталы и выделы», «Экосистемы, разрезанные квартальной сетью» или «Слой экосистем с уникальным ID», выбор файла (и слоя, если это GeoPackage) и сопоставление полей. Поля подбираются автоматически по типичным именам; ниже выводится число полигонов, типы, которые распознают правила (лес, луг, водные, околоводные), и проверка уникальности ID. В режиме `kv_cut` дополнительно запрашивается вектор квартальной сети: файл, поле с уникальным номером квартала и (если есть) поле ООЗТ в сети.
3. Тематические слои — для каждого указано, что в нём должно быть, для каких включённых мероприятий он нужен и какие файлы выбраны. Отметка «!» означает, что слой нужен включённым мероприятиям, но не выбран. Выбор файлов — через окно Проводника, для большинства слоёв можно выбрать несколько файлов сразу. Слои видов и редких экосистем — общий список: для каждого файла задаются категория, группа организмов и (при необходимости) поле названия, тип данных определяется сам; ниже показано, сколько слоёв подходит каждому мероприятию.
4. Что будет рассчитано — все мероприятия таблицы со статусом при текущем наборе данных: «будет рассчитано», «не хватает: …», «в слое нет полигонов типа …», «выключено в таблице», «нет данных». По щелчку на строке показываются метод выявления из Excel, правило назначения и откуда оно взято, все параметры (из таблицы, по умолчанию или из окна скрипта), полное описание расчёта, нужные данные и подходящие слои видов.
5. Результаты — папка, кварталы или листы для отчёта, подложка, форматы отчёта (Word DOCX, PDF, Word 97–2003 DOC).

Кнопки «Загрузить конфигурацию» и «Сохранить конфигурацию» читают и записывают тот же JSON, что принимает `--config`. Перед запуском окно проверяет обязательные поля и, если части включённых мероприятий не хватает данных, перечисляет их и спрашивает подтверждение. Тот же список статусов записывается в начало `run.log`.

## Единицы территории

| Режим | `unit_mode` | Обязательные поля | Группировка отчёта и схем |
| --- | --- | --- | --- |
| Кварталы и выделы | `kv_vyd` | ООЗТ, квартал, выдел, тип | по кварталам |
| Экосистемы, разрезанные квартальной сетью | `kv_cut` | тип (экосистемы) + вектор квартальной сети и поле номера квартала | по кварталам |
| Слой экосистем с уникальным ID | `eco` | уникальный ID, тип | по листам регулярной сетки `sheet_size_m` (по умолчанию 1000 м, листы A1, A2…, ряды с севера) или по значениям поля `report_group_field` |

В режиме `kv_cut` подаются два слоя: экосистемы (`oozt_path`, обязательное поле — тип; название, ООЗТ и исходный ID — по желанию) и квартальная сеть (`kvnet_path` + `kvnet_field` — поле с уникальным номером квартала; `kvnet_oozt_field` — поле ООЗТ в сети, если оно там есть). Экосистемы разрезаются границами кварталов: в каждом квартале возникает своя нумерация выделов — с 1, от северо-западного угла квартала, с запада на восток, с севера на юг (по положению центроида). Дальше всё как в режиме «Кварталы и выделы» (см. ниже). Кусочки мельче `min_cut_ha` (по умолчанию 0,01 га) отбрасываются, площадь экосистем вне квартальной сети отмечается в журнале.

Учётная единица мероприятий — квартал: таблицы, GeoPackage и отчёты оперируют парами «ООЗТ — квартал» (слои `kvartal_measures` и `measures`), без отдельных выделов. Границы выделов (или полигонов экосистем) используются только как геометрия для расчёта участков работ — зон, где мероприятие выполняется (слой `measure_zones`). В режиме `eco` всё то же по листам сетки.

В режиме экосистем поле названия и поле ООЗТ необязательны: без поля ООЗТ используется `oozt_name`, без названия — тип полигона. Полигон относится к листу по своей внутренней точке. В таблицах колонки называются «Лист» (или по имени поля группировки), «ID экосистемы», «Тип полигона»; в GeoPackage слой называется `eco_measures` и содержит исходные атрибуты, лист или группу отчёта и перечень мероприятий. Правила расчёта во всех режимах одинаковы.

Поле типа должно содержать слова, по которым правила узнают экосистемы: «лес…», «луг…», «водн…», «околовод…» или «болот…». Уточнённые типы сопоставляются по словам: правило «луговые естественные» не срабатывает на типе «Луговые антропогенные», а правило «луговые» — срабатывает на любом типе со словом «луг».

### Порог доли полигона

Мероприятия, основание которых — участок внутри полигона (плотность троп в окне, тропы у воды, уклон по ЦМР, плотность врановых, зоны SDM инвазионных и редких видов), назначаются полигону, только если такой участок занимает не меньше 25% его площади (`min_share_pct`, поле «Общий порог» в окне выбора данных; 0 — без порога; для отдельного мероприятия можно задать свой порог в столбце «Мин. доля полигона, %»). Без порога крупный полигон получал мероприятие целиком из-за нескольких квадратных метров участка. Доля указывается в основании назначения; сами участки работ — в слое `measure_zones`. Порог не применяется к назначениям по типу полигона, по плотности троп на полигон, по точкам и полигонам находок видов и по тропам у редких видов — у них нет площадной доли.

### Многочастные объекты

Если объект слоя территории состоит из нескольких контуров (MultiPolygon — например, все участки одной экосистемы записаны одним объектом), по умолчанию он делится на отдельные контуры: мероприятие назначается каждому конкретному контуру, а не объекту целиком. ID контуров — «ID-1», «ID-2», … (крупнейший — первый); части меньше 0,01 га остаются при ближайшем крупном контуре. Отключается флажком в окне, `"split_multipart": false` в конфигурации или `--no-split`.

### Слой стихийных троп из OSM

Стихийные (необорудованные) тропы кодируются в OpenStreetMap тегом `informal=yes` на линиях `highway=path`/`footway`. Скрипт скачивает их сам: при запуске через Overpass API ([overpass-api.de](https://overpass-api.de/api/interpreter) и зеркала) запрашиваются все линии `informal=yes` в границах территории (с запасом на буферы правил), результат сохраняется в `out_dir/informal_trails_osm.geojson` (WGS 84) и загружается как отдельный слой. Скачивание включается галочкой «Стихийные тропы: скачивать из OSM» в окне или ключом `informal_trails: ["auto"]` в конфигурации; вместо скачивания можно указать пути к локальным файлам. Если интернет недоступен, скрипт пишет предупреждение в журнал и продолжает работу без слоя — правила «только стихийные тропы» переходят на всю дорожно-тропиночную сеть.

Слой используют мероприятия со столбцом «Только стихийные тропы» = да (III.3, III.4 — «Борьба с фрагментацией», «Временные ограничения»): у них правило «виды: тропы у находок» считает тропы только по `informal=yes`, а не по всей сети. Скачивание выполняется, только если такой столбец включён хотя бы у одного активного мероприятия.

Косвенный признак стихийной тропы, если тег `informal` не заполнен: `highway=path` + `surface=ground/dirt/grass` без `lit` и `operator`. Для фильтров водоёмов (столбцы «Водоёмы (только/кроме)») слой гидрографии должен содержать поле с названиями (`NAME`/`NAME_RU`).

### Категории Красной книги Москвы

При загрузке слоёв видов скрипт автоматически определяет категорию Красной книги Москвы для каждой записи: латинское название вида сопоставляется со справочником `refdata/kk_moscow.csv` (3-е издание Красной книги Москвы, утверждено [постановлением Правительства Москвы № 745-ПП от 02.07.2019](https://www.mos.ru/upload/documents/docs/745-PP(2).pdf), Приложение 2 — 564 позиции). Категории: 0 — исчезнувшие, 1 — под угрозой исчезновения, 2 — редкие или малочисленные с сократившейся численностью, 3 — уязвимые, 4 — неопределённого статуса, 5 — восстановившиеся; «О» — особая пометка издания. Изменения в списке 2022 и 2026 годов в справочник не включены.

Новый столбец таблицы мероприятий «КК Москвы: категории» ограничивает мероприятие видами с указанными категориями (например, III.3 и III.4 — «1, 2, 3»). Сопоставление идёт по первым двум словам латинского названия без учёта авторов и синонимов в скобках; вид без категории (пусто в ячейке) не учитывается. Если справочник не найден, в журнале — предупреждение, фильтр по категориям не срабатывает.

### Инвазивные виды: II.1 борщевик, II.2 прочие

Мероприятие II.1 — «Удаление борщевика Сосновского» (таксон `Heracleum sosnowskyi`; точки, полигоны, SDM с порогом 0,95). II.2 — «Удаление прочих инвазивных видов растений»: 33 таксона из перечня инвазивных видов к [постановлению Правительства Москвы № 369-ПП от 03.03.2026](https://base.garant.ru/413816164/) — справочник `refdata/invasive_moscow.csv` (34 позиции) без борщевика. Все точки и полигоны находок учитываются; SDM ≥ 0,95 — отдельная строка «мониторинг». Карантинная Ambrosia artemisiifolia в перечень 369-ПП не входит и в списке II.2 отсутствует — если её находки и SDM нужно учитывать, добавьте таксон в столбец «Виды: таксоны» строки II.2.

## Порядок и схемы

Кварталы, листы, индексы поля группировки и ID упорядочиваются естественно: числа — по значению (1110, 5110, 9110, 11110, 44504), текст с номерами — по номерам. В конце отчёта приводится «Перечень мероприятий к выполнению»: одна строка на полигон, мероприятия с пунктами Приказа, в том же порядке.

На схемах подписывается только номер текущего квартала (или листа/индекса); соседние кварталы показаны светло-серой заливкой с номерами без выделов. Подложка схемы (снизу вверх): OpenStreetMap (при включённой подложке), полупрозрачная тепловая карта рекреации (порог 0,95 по плотности точек), озёра и пруды, реки и канавы (включая дренаж), горизонтали по ЦМР через 2,5 м, грунтовые дороги (слабо), твёрдые дороги (жирно), стихийные тропы, основания и мероприятия. Контекстные слои рисуются только в границах ООЗТ. Если подписать все полигоны нельзя, в углу схемы указано, сколько подписано, — полный перечень есть в таблицах. В режиме поля группировки (индексы — типы, полигоны разбросаны по территории) прочие полигоны показаны тонким серым контуром без подписей.

## Форматы отчёта

Форматы задаются флажками в окне, ключом `report_formats` в конфигурации (по умолчанию `["docx", "pdf"]`) или параметром `--formats`. `report.md` создаётся всегда.

| Формат | Как создаётся |
| --- | --- |
| DOCX | встроенная запись средствами стандартной библиотеки Python, внешние пакеты не нужны |
| PDF | из DOCX через Microsoft Word; если Word недоступен — через LibreOffice; если нет ни того, ни другого — встроенной вёрсткой matplotlib с той же структурой (А4 альбомная, схемы, таблицы с переносом по страницам) |
| DOC | из DOCX через Microsoft Word или LibreOffice; без них не создаётся (в журнале будет предупреждение) |

Способ, которым создан каждый файл, записывается в `run.log`. Если файл отчёта открыт в другой программе, скрипт сообщит об этом; закройте файл и пересоберите отчёт с `--report-only`.
