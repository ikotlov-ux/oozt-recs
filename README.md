# oozt-recs

Автоматизированное формирование природоохранных рекомендаций (мероприятий) для особо охраняемых зелёных территорий (ООЗТ) и природных территорий города Москвы. Скрипт назначает мероприятия по кварталам и выделам либо по полигонам слоя экосистем с уникальным ID на основе ГИС-слоёв, ЦМР и данных о встречаемости видов, для каждого назначения формирует текстовое основание с числовыми значениями и собирает картографические схемы и отчёт.

## Нормативная основа

Перечень мероприятий и их нумерация соответствуют разделу 4 «Мероприятия по сохранению биоразнообразия при проведении работ по содержанию ООЗТ и ПТ» Временного регламента содержания особо охраняемых зелёных территорий и природных территорий города Москвы, утверждённого совместным приказом Правительства Москвы от 30.12.2025 № 05-09-310/25 (и др.), пункты 4.1–4.13. Отдельные позиции соответствуют инженерно-техническим и противоэрозионным мероприятиям (ИПЭЭ-1…ИПЭЭ-3).

## Реализованные правила

| Код | Мероприятие | Пункт | Метод выявления |
| --- | --- | --- | --- |
| I.3 | Создание условий для самовосстановления покрова | 4.3 | плотность троп на выдел (м/га), верхний квартиль по выборке выделов |
| I.7 | Регулируемое мозаичное выкашивание травостоя | 4.9 | все луговые сообщества |
| I.8 | Частичное удаление деревьев и кустарников на болотах | 4.12 | все водные и околоводные сообщества |
| I.9 | Принудительная аэрация | 4.12 | все водные сообщества |
| I.10 | Укрепление берегов | ИПЭЭ-1 | тропы по периметру водных объектов, скользящее окно 50 м |
| II.1 | Удаление чужеродных инвазивных видов растений | 4.1 | точки, полигоны и SDM-растры с вероятностью ≥ 0,95 |
| III.1 | Сохранение почвозащитного подлесочного яруса | 4.2 | растровая плотность троп, скользящее окно 50 м, верхний квартиль |
| III.3 | Ликвидация стихийных троп с восстановлением покрова | 4.3 | тропы в 50 м от точек редких видов, SDM ≥ 0,75 |
| III.4 | Установка временных ограничений рекреации | 4.7 | тропы в 50 м от точек редких видов, SDM ≥ 0,75 |
| III.5 | Защита обезлесенных склонов от эрозии | ИПЭЭ-2 | уклон по ЦМР более 5 % и луговые экосистемы |
| III.5 | Посадка и обработка по горизонталям, террасирование | ИПЭЭ-3 | уклон по ЦМР более 7 %, любые экосистемы |
| IV.5 | Контроль численности врановых в период гнездования | — | плотность точек рода *Corvus*, окно 500 м, верхний квартиль |

Остальные мероприятия раздела 4 в расчёт не входят: часть требует передачи готовых слоёв данных (наблюдения орнитологов и зоологов, слои рубок, дренажной сети, площадок отдыха), часть — разработки метода дистанционного выявления.

## Основные параметры

Задаются константами в начале файла `oozt_recs.py`:

| Параметр | Значение | Смысл |
| --- | --- | --- |
| `CELL` | 10 м | шаг сетки растров плотности и уклона |
| `TRAIL_WINDOW_M` | 50 м | радиус скользящего окна плотности троп |
| `CORVUS_WINDOW_M` | 500 м | радиус окна плотности врановых |
| `RARE_BUFFER_M` | 50 м | буфер от точек редких видов |
| `SHORE_BUFFER_M` | 50 м | буфер вдоль водных объектов для укрепления берегов |
| `SDM_THRESHOLD_RARE` | 0,75 | порог вероятности SDM для редких видов |
| `SDM_THRESHOLD_INVASIVE` | 0,95 | порог вероятности SDM для инвазионных видов |
| `QUANTILE` | 0,75 | «верхний квартиль» для порогов плотности |

Пороги уклона (5 % и 7 %) считываются из формулировки метода в таблице мероприятий.

## Требования

Python 3.10 и новее, окружение с геопространственными пакетами:

```
geopandas, pyogrio, rasterio, shapely, numpy, pandas, scipy, matplotlib, openpyxl
```

Дополнительно: `contextily` — подложка OSM на схемах, `python-docx` — отчёт в формате DOCX (без него отчёт формируется только в Markdown), `tkinter` — окно выбора исходных данных (входит в стандартную поставку Python и conda).

Пример создания окружения:

```bash
conda create -n gis python=3.11 geopandas pyogrio rasterio shapely scipy matplotlib openpyxl contextily -c conda-forge
conda activate gis
pip install python-docx
```

## Запуск

```bash
# окно выбора исходных данных
python oozt_recs.py

# повторный запуск с сохранённой конфигурацией, без окна
python oozt_recs.py --config config_local.json

# то же окно, предзаполненное из конфигурации: можно поправить слои и запустить
python oozt_recs.py --config config_local.json --gui

# отчёт только по выбранным кварталам (или листам / группам в режиме экосистем)
python oozt_recs.py --config config_local.json --kv 1,2,17,40
python oozt_recs.py --config config_eco.json --kv B3,C4

# пересобрать только отчёт по уже рассчитанной таблице
python oozt_recs.py --config config_local.json --report-only

# без подложки OSM
python oozt_recs.py --config config_local.json --no-basemap
```

Скопируйте `config.example.json` (кварталы и выделы) или `config.example_eco.json` (слой экосистем) в `config_local.json` и подставьте свои пути. Файлы `config_local*.json`, `config_pc.json` и `config_used.json` исключены из репозитория, чтобы локальные абсолютные пути не попадали в историю.

## Окно выбора данных

Все исходные данные задаются в одном окне из пяти блоков:

1. Таблица мероприятий — сразу после выбора показано, сколько мероприятий в таблице и сколько из них включено.
2. Слой территории — режим «Кварталы и выделы» или «Слой экосистем с уникальным ID», выбор файла (и слоя, если это GeoPackage) и сопоставление полей. Поля подбираются автоматически по типичным именам; ниже выводится число полигонов, типы, которые распознают правила (лес, луг, водные, околоводные), и проверка уникальности ID.
3. Тематические слои — для каждого указано, что в нём должно быть, для каких включённых мероприятий он нужен и какие файлы выбраны. Отметка «!» означает, что слой нужен включённым мероприятиям, но не выбран. Выбор файлов — через окно Проводника, для большинства слоёв можно выбрать несколько файлов сразу.
4. Что будет рассчитано — все мероприятия таблицы со статусом при текущем наборе данных: «будет рассчитано», «не хватает: …», «в слое нет полигонов типа …», «выключено в таблице», «нет данных». По щелчку на строке показываются метод выявления из Excel, правило скрипта и нужные слои.
5. Результаты — папка, кварталы или листы для отчёта, подложка.

Кнопки «Загрузить конфигурацию» и «Сохранить конфигурацию» читают и записывают тот же JSON, что принимает `--config`. Перед запуском окно проверяет обязательные поля и, если части включённых мероприятий не хватает данных, перечисляет их и спрашивает подтверждение. Тот же список статусов записывается в начало `run.log`.

## Единицы территории

| Режим | `unit_mode` | Обязательные поля | Группировка отчёта и схем |
| --- | --- | --- | --- |
| Кварталы и выделы | `kv_vyd` | ООЗТ, квартал, выдел, тип | по кварталам |
| Слой экосистем с уникальным ID | `eco` | уникальный ID, тип | по листам регулярной сетки `sheet_size_m` (по умолчанию 1000 м, листы A1, A2…, ряды с севера) или по значениям поля `report_group_field` |

В режиме экосистем поле названия и поле ООЗТ необязательны: без поля ООЗТ используется `oozt_name`, без названия — тип полигона. Полигон относится к листу по своей внутренней точке. В таблицах колонки называются «Лист» (или по имени поля группировки), «ID экосистемы», «Тип полигона»; в GeoPackage слой называется `eco_measures` и содержит исходные атрибуты, лист или группу отчёта и перечень мероприятий. Правила расчёта в обоих режимах одинаковы.

Поле типа должно содержать слова, по которым правила узнают экосистемы: «лес…», «луг…», «водн…», «околовод…» или «болот…».

## Входные данные

Обязательны только таблица мероприятий (`measures_xlsx`) и слой территории (`oozt_path`). Остальные слои опциональны: соответствующие правила просто пропускаются с записью в журнал.

| Ключ конфигурации | Содержание |
| --- | --- |
| `measures_xlsx` | таблица «Мероприятия по Приказу»: мероприятие, тип экосистемы, пункт, признак включения, метод выявления |
| `unit_mode` | `kv_vyd` — кварталы и выделы, `eco` — слой экосистем с уникальным ID |
| `oozt_path`, `oozt_layer` | слой территории (для GeoPackage — имя слоя) |
| `fields` | сопоставление полей: `OOZT`, `KV`, `VYD`, `TYPE`, `NAME` или `ID`, `TYPE`, `NAME`, `OOZT` |
| `oozt_name`, `report_group_field`, `sheet_size_m` | режим `eco`: название ООЗТ, поле группировки отчёта, размер листа сетки, м |
| `dem_path` | цифровая модель рельефа для расчёта уклонов |
| `trails` | линии дорожно-тропиночной сети (OSM highway или собственные съёмки) |
| `hydro_lines`, `hydro_polys` | линейные и полигональные водные объекты |
| `invasive_points`, `invasive_polys`, `invasive_rasters` | встречаемость инвазионных видов, включая растры SDM |
| `rare_points`, `rare_polys`, `rare_rasters` | встречаемость редких и охраняемых видов, включая растры SDM |
| `fauna_points` | точки наблюдений животных, в том числе рода *Corvus* |

## Результаты

Всё складывается в `out_dir`:

| Файл | Содержание |
| --- | --- |
| `measures_long.xlsx`, `measures_long.csv` | длинная таблица ООЗТ — квартал (лист) — выдел (ID) — мероприятие с основанием и числовым значением; в Excel также листы «мероприятия по приказу» и сводка по полигонам `by_vydel` |
| `evidence.gpkg` | слои-основания (точки, линии, полигоны) и полигоны с назначенными мероприятиями (`vydel_measures` или `eco_measures`), EPSG:4326 |
| `report/report.md` | отчёт по кварталам или листам: схема и таблицы мероприятий, сгруппированные по типу мероприятий, типу экосистемы и пункту приказа |
| `report/fig_*.png` | картографические схемы кварталов или листов |
| `config_used.json` | фактическая конфигурация запуска, пригодна для передачи в `--config` |

Координаты в отчётах приводятся в WGS 84 (десятичные градусы), выходные слои сохраняются в EPSG:4326.
